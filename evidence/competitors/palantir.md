# Palantir

Palantir provides strong architectural evidence that operational AI is more useful when it sits on top of a coherent enterprise representation.

Palantir describes its standard architecture as AIP + Foundry + Apollo. Foundry provides data operations; AIP provides generative-AI capabilities; Apollo manages continuous delivery.

At the centre is the **Ontology**, which Palantir describes as integrating enterprise data, logic, action, and security into an operational representation that humans and AI agents can use.

Simplified:

```text
DATA + SYSTEMS
↓
ONTOLOGY / ENTERPRISE REPRESENTATION
↓
OPERATIONS + DECISIONS
↓
AI / AGENTS / AUTOMATION
```

## What this validates

- AI benefits from structured enterprise context
- enterprise representations can connect data to real-world objects/actions
- continuous feedback can improve operational systems
- forward-deployed engineering can connect product development closely to real enterprise problems

## What it does not validate

Project Kaizen is not automatically differentiated because Palantir exists. In fact, Palantir demonstrates that parts of the enterprise-intelligence thesis are already being built at significant depth.

Project Kaizen must explain what its diagnostic/orchestration model does that a platform company, integrator, or FDE team does not.
