# Adversarial Reasoning

The agent layer should not exist to produce six parallel reports.

It should create disciplined disagreement.

## Basic loop

```text
HYPOTHESIS
↓
SIX PERSPECTIVES ATTACK IT
↓
AGREEMENTS AND CONTRADICTIONS
↓
WHAT EVIDENCE WOULD RESOLVE THEM?
↓
NEW QUESTIONS
↓
NEW EVIDENCE
↓
UPDATED HYPOTHESIS
↺
```

## Contradiction mining

Look for gaps between:

- stated process and actual process
- strategy and resource allocation
- management narrative and system evidence
- claimed decentralisation and approval logs
- customer obsession and support outcomes
- AI ambition and missing data foundations

Contradictions are diagnostic signals, not automatic proof of dishonesty.

## Counterfactuals

Useful questions include:

- If AI did not exist, how would we solve this?
- If this company were founded today, would this process exist?
- If the founder disappeared for six months, what would stop?
- If revenue doubled tomorrow, what would break first?
- If revenue halved, what structure becomes unsustainable?

## Pre mortem

Assume the intervention failed badly twelve months from now.

Each role explains why.

Use recurring failure modes to redesign before deployment.

## Post mortem

After deployment, ask which assumptions were wrong, what changed unexpectedly, and whether the same intervention should be recommended again under similar conditions.

## Jury review

For major recommendations, the six roles can issue positions such as:

```text
YES
NO
NOT YET
YES IF...
INSUFFICIENT EVIDENCE
```

Do not use majority voting as truth.

The useful output is the disagreement, assumptions, blockers, and evidence required.
